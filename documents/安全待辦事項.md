以下是針對目前程式、部署設定與實際運行狀態的檢視結果。重點先說結論：

- **程式碼層的 SQL injection、command injection、zip slip 風險目前看起來很低**：查詢使用 SQLAlchemy 參數化、workflow 是白名單且 subprocess 使用參數陣列、壓縮檔沒有 `extractall`。
- **最大風險不是程式碼注入，而是「幾乎沒有認證／授權」加上「CORS 全開」**。目前任何能連到 API 的人或網站，都可以直接讀取管理資訊、觸發下載／索引／停止流程，甚至修改題庫與 benchmark。
- **PostgreSQL 與 Qdrant 直接綁定在 `0.0.0.0`，且使用預設帳密／沒有 API key**，這是另一個高風險項目。
- 另外還有 **SSRF（Ollama 主機管理）**、**敏感資訊暴露**、**資源耗盡**、**缺少安全標頭／CSP**、**稽核身分可偽造**、**提問與答案被保存並公開可讀** 等問題。

以下依風險等級整理。

## P0：應立即處理

### 1. 沒有認證／授權，管理與寫入 API 直接暴露

**證據**
- CORS 預設 `*`：`src/judgment/config.py:53`
- 允許 `GET / POST / PATCH / DELETE` 與任意 headers：`src/judgment/web/app.py:724-733`
- 實際測試：
  - `Origin: https://evil.example` 取得 `access-control-allow-origin: *`
  - `OPTIONS /api/processing/update` 回傳允許 `POST`
- OpenAPI 目前約有 **40 個 POST／PATCH／DELETE 端點**，包含：
  - `/api/processing/update`、`/api/processing/stop`
  - `/api/processing/workflows/{workflow_id}/run`
  - `/api/question-bank/*` 的新增／修改／刪除／審核／匯入
  - `/api/benchmark/*` 的 suite／run／review
  - `/api/ollama/hosts/*` 主機新增／啟用／刪除
  - `/api/index-versions/*/activate`、`/rollback`
  - `/api/llm/model`、`/api/test-mode`
- 這些 handler 沒有 `Depends(...)`、API key、session 或角色檢查。
- `src/judgment/web/app.py:1443-1446` 的 `_actor()` 只讀 `X-Judgment-Actor`，任何呼叫者都能自稱任何審核者。

**影響**
- 任何網站都能對 `http://127.0.0.1:9200` 發動請求；若後端透過 cloudflared 對外，等於整個網際網路都能操作。
- 可觸發大量下載／索引／LLM 工作、停止正在執行的流程、修改或刪除題庫、偽造 benchmark 審核、切換模型與索引 alias。
- 當時「未登入者不得提問或檢視判決」的 Google 登入需求尚未實作；後續已於 2026-11-18 完成 Google 實機登入與 admin session 驗證。

**建議**
- 立即用 **Cloudflare Access** 保護 cloudflared 端點，或先停止對外 tunnel。
- CORS 改為明確的 Pages／本機來源，不要使用 `*`。
- 所有非唯讀 API 加上 admin 認證與角色檢查；敏感 GET（`/api/performance`、`/api/system-usage`、`/api/processing`）也要保護。
- 若使用 cookie session，必須加上 CSRF token；不要同時使用 `allow_origins=*` 與 credentials。
- 量產環境關閉或保護 `/api/docs`、`/api/openapi.json`。
- 將 `X-Judgment-Actor` 改為由認證身分取得，不可信任請求 header。

### 2. Ollama 主機管理可被用作 SSRF

**證據**
- `normalize_host_url()` 只檢查 `http/https` 與 port，允許任意主機、IP、內網位址：`src/judgment/ollama_hosts.py:38-54`
- 新增主機後，`list_hosts()` 會對 `base_url + /api/tags` 發出請求：`src/judgment/ollama_hosts.py:72-101`
- 能力測試會對 `base_url + /api/show` 發出 POST：`src/judgment/llm_capabilities.py:103-106`
- 沒有私網／loopback／link-local／metadata IP 封鎖，也沒有主機數量上限。

**影響**
- 攻擊者可新增 `http://127.0.0.1:xxx`、`http://169.254.169.254`、內網服務 IP，再利用列表或能力測試讓後端代為連線。
- 可用來探測內網連接埠、讀取錯誤訊息、對內部 HTTP 服務發出請求。
- 大量新增主機也會造成執行緒與網路資源消耗。

**建議**
- 主機 allowlist，或至少封鎖 loopback、private、link-local、metadata IP。
- DNS 解析後再檢查實際 IP，避免 DNS rebinding。
- 限制主機數量與探測頻率。
- 這個端點必須要求 admin 權限。
- 若只需要固定幾台 Ollama，改用環境設定而非線上 CRUD。

### 3. PostgreSQL／Qdrant 直接暴露且使用預設憑證

**證據**
- `docker-compose.yml:9-10`：`"5432:5432"`
- `docker-compose.yml:22-24`：`"6333:6333"`、`"6334:6334"`
- 實際 `docker ps` 顯示：
  - `judgment-postgres 0.0.0.0:5432->5432/tcp`
  - `judgment-qdrant 0.0.0.0:6333-6334->6333-6334/tcp`
- 當時 PostgreSQL 預設帳密為 `judgment/judgment`：`docker-compose.yml:6-8`、`.env.example:1`；後續已改由 `.env` 的 `POSTGRES_PASSWORD` 提供。
- 當時 `.env` 的 `QDRANT_API_KEY` 為空；後續已設定。

**影響**
- 同網段、VPN、Tailscale 或任何可達主機的裝置，可以直接連線 PostgreSQL／Qdrant。
- PostgreSQL 可讀寫題庫、benchmark、performance records（內含 RAG 問題與答案）。
- Qdrant 沒有 API key 時，可列舉、修改或刪除 collection。
- 不需要經過 Web API 的認證（目前也沒有認證）。

**建議**
- 改成只綁 loopback：
  ```yaml
  ports:
    - "127.0.0.1:5432:5432"
    - "127.0.0.1:6333:6333"
  ```
- 若不需要外部 gRPC，移除 `6334` 或同樣綁 `127.0.0.1`。
- 立即更換 PostgreSQL 密碼，設定強密碼並同步 `.env`。
- 設定 Qdrant API key。
- 用防火牆／Security Group 限制來源；需要遠端存取時走 SSH tunnel 或 Tailscale，不要公開資料庫埠。
- 檢查既有 log／連線紀錄是否有異常來源。

### 4. 敏感內部資訊與使用者內容暴露

**證據**
- `/api/system-usage` 回傳專案絕對路徑、資料目錄、Docker CLI 路徑、Parquet 路徑：`src/judgment/web/system_usage.py:608-645`
- `/api/status` 回傳 `parquet_path`、內部服務 URL、環境名稱、完整 API endpoint catalog：`src/judgment/web/status.py:155-168`
- `/api/processing` 回傳 `state_path`、workflow `log_path`、PID：`src/judgment/web/processing.py:5290-5309`、`:5398-5412`
- `/api/performance` 會回傳 RAG 的 `question` 與 `answer`：
  - 寫入：`src/judgment/web/app.py:2202-2203`、`:2274-2275`
  - 讀取：`src/judgment/web/performance.py:625-669`
- 實際測試 `/api/performance?process=RAG%20問答` 可直接看到完整問題與回答。
- 多處 500 錯誤直接回傳 `ExceptionClass: message`，例如 `app.py:1400` 附近、`app.py:1438-1440`。

**影響**
- 洩漏主機目錄結構、服務拓撲、內部 hostname／port、log 路徑與執行 PID。
- RAG 問題與答案可能包含敏感法律諮詢內容或個資；目前任何能呼叫 API 的人都能讀取。
- 錯誤訊息可能包含資料庫連線、檔案路徑或 SQL 細節。

**建議**
- 將 `/api/system-usage`、`/api/processing`、`/api/status` 的詳細資訊移到 admin-only 端點。
- 對外回應只保留健康狀態、版本與必要計數，路徑以 `…` 或相對路徑取代。
- 預設不保存 RAG 問題與答案，或至少做遮罩、加密、縮短保留期。
- 500 錯誤只回傳通用訊息與 request id，詳細內容寫入伺服器日誌。
- 替 `performance_records.flow.metadata` 增加欄位級紅留政策。

### 5. 沒有速率限制、請求大小限制與併發保護

**證據**
- 沒有 rate limiting middleware。
- `/api/rag/query`、`/api/rag/query/stream`、`/api/quality`、`/api/processing`、`/api/system-usage`、`/api/benchmark/runs`、`/api/question-bank/ai-items` 等皆可匿名呼叫。
- `QueryRequest.filters` 是任意 `Dict[str, Any]`，沒有欄位長度上限。
- `question-bank/import` 可一次送大量題目。
- PostgreSQL 沒有設定 `statement_timeout`；DuckDB 品質掃描沒有記憶體上限。
- SSE 沒有最大連線數限制。
- 同步 endpoint 使用 threadpool，昂貴查詢同時進來可能耗盡 threadpool／DB pool。

**影響**
- 單一使用者即可造成 CPU／GPU／DB／磁碟／網路耗盡。
- 大量 SSE 連線或 `/api/processing` 請求會拖慢整個主控台。
- 大量 RAG 請求會讓 Ollama 佇列爆滿，影響正常使用者。

**建議**
- 在 Cloudflare 或 FastAPI 加上 per-IP／per-user rate limit，特别是 POST、RAG、SSE。
- 設定 request body 大小上限與欄位長度上限。
- 對 RAG、benchmark、quality、processing 使用 semaphore／queue，限制同時執行數。
- PostgreSQL 設定 `statement_timeout`；DuckDB 設定 `memory_limit`／`threads`。
- 為 `/api/home`、`/api/status`、`/api/quality`、`/api/processing` 加上短 TTL 快取或 ETag，避免每個使用者重複掃描。
- 回傳 `429 Too Many Requests` 與 `Retry-After`。

### 6. 缺少安全標頭、CSP 與點擊劫持防護

**證據**
- FastAPI 首頁回應沒有 `X-Frame-Options`、`Content-Security-Policy`、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`：
  - 實際 `curl -I http://127.0.0.1:9200/` 只有基本標頭。
- `frontend/_headers` 有部分標頭，但只對 Cloudflare Pages 生效：`frontend/_headers:1-5`
- 首頁有 inline script：`src/judgment/web/static/index.html:21-56`
- 使用外部 Google Fonts，沒有 SRI：`index.html:13-18`

**影響**
- 可被 iframe 嵌入，搭配管理按鈕進行 clickjacking。
- 若未來出現 XSS，沒有 CSP 作為第二層防護。
- 外部字型请求會洩漏使用者 IP 給第三方，也不利離線／file:// 使用。

**建議**
- 在 FastAPI 加上 security headers middleware：
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY` 或 CSP `frame-ancestors 'none'`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: geolocation=(), microphone=(), camera=()`
  - HTTPS 環境加 `Strict-Transport-Security`
- 加 CSP；inline theme script 改用外部檔案或 nonce/hash。
- 將 Google Fonts 自架到 `assets/fonts`，移除第三方請求。
- Cloudflare Pages 的 `_headers` 也補上 CSP。

### 7. 稽核身分可偽造、題庫審核可被繞過

**證據**
- `_actor()` 直接信任 `X-Judgment-Actor`：`app.py:1443-1446`
- `create_item()` 可從 payload 直接指定 `status`：`question_bank.py:475-480`
- `update_item()` 可把 `status` 設成任何 `QUESTION_STATUSES`，包含 `accepted`：`question_bank.py:582-590`
- `/api/question-bank/items/{id}/review` 沒有角色檢查。

**影響**
- 任何呼叫者都可以建立「已接受」題目，或把題目改成 accepted，繞過人工審核。
- `reviewed_by` 可偽造成任何名字，稽核紀錄不可信。
- Benchmark 題庫與 regression gate 的資料完整性受影響。

**建議**
- 題目狀態只能由受權限保護的 review transition 改變；一般 create/update 不允許直接設定 `accepted`。
- `reviewed_by` 必須由登入身分取得。
- 建立不可變的 audit log（操作者、時間、舊值／新值、request id）。
- 題庫與 benchmark 寫入端點全部加 admin 權限。

### 8. `.env`、日誌與備份的機密保護不足

**證據**
- 實際檔案權限：`.env` 為 `0644`，`.run/*.log` 多為 `0644`。
- `backup.sh:369-371` 會把 `.env` 複製到備份的 `config/.env`。
- README 已提醒備份可能含資料庫密碼、需加密：`README.md:167`。
- `power_agent.py:159`、`:455` 會把 `--database-url` 放在子程序命令列，可能被同機其他使用者用 `ps` 看到。

**影響**
- 同機其他使用者可讀取 OpenData 帳密、DB 連線字串、內部路徑與錯誤訊息。
- 備份遺失或未加密時，等於洩漏完整資料庫與憑證。
- `ps` 可能暴露資料庫密碼。

**建議**
- `.env` 改 `0600`，`.run` 目錄與日誌改 `0700`／`0600`。
- 備份預設加密（age／GPG）並在文件中要求；至少備份目的地權限 0700。
- 不要把 `DATABASE_URL` 放在命令列；改用環境變數或 secret manager。
- 定期輪換 OpenData／DB／Qdrant 憑證。
- 檢查 `.run` 日誌是否含敏感內容，加入 log rotation 與遮罩。

## P2：防禦縱深與中長期加強

### 9. `?api=` 可被用來導向惡意 API

**證據**
- `api.js:49-85`：URL 的 `?api=` 具有最高優先權，可指向任意 http(s) 位址。
- `localStorage` 也可保存任意 API base。

**影響**
- 攻擊者可分享 `...?api=https://evil.example#/rag`，使用者輸入的法律問題就會送到攻擊者伺服器；攻擊者也可回傳偽造的引用與答案。
- 屬於 phishing／資料外洩風險，不是傳統 XSS。

**建議**
- 只允許同源、`127.0.0.1`、`localhost` 或明確 allowlist 的 API base。
- 變更 API base 時顯示警告與目前來源。
- 不要把 `?api=` 當成永久設定來源；或加上簽章／一次性 token。

### 10. URL scheme 與前端注入防護

**現況**
- 大多數文字都有 `escapeHtml`，包含 RAG answer、判決全文、題庫、benchmark。
- 沒有發現明顯未轉義的文字插入。
- 但 `href="${escapeHtml(url)}"` 只做 HTML escape，沒有檢查 `javascript:`／`data:` scheme；例如 `pages/data.js:1363`、`rag.js:465` 的 PDF／法規連結。

**影響**
- 若 OpenData、DB 或題庫資料被竄改，惡意 URL 可能造成點擊後執行或釣魚。
- 目前資料來源相對可信，所以風險較低，但應作 defense-in-depth。

**建議**
- 新增 `safeUrl()`：只允許 `http:`／`https:`（必要時 `mailto:`），其他顯示為純文字。
- 對 `style` 中的顏色值做格式驗證，避免 CSS injection。
- 若未來加入 Markdown，使用 DOMPurify 或嚴格的白名單渲染。
- 加 CSP 作為第二層。

### 11. Prompt injection 與引用正確性

**證據**
- RAG 直接把判決／法規內容放進 prompt：`src/judgment/rag.py:931-1008`
- 引用驗證只檢查 `[n]` 是否落在範圍內：`rag.py:1185-1200`
- 沒有檢查「引用內容是否真的支持該結論」。

**影響**
- 判決或法規文字若含對 LLM 的指令，可能誘導模型產生錯誤結論。
- 即使引用編號有效，也可能引用錯條文；對法律問答而言是信任風險。
- 目前沒有工具呼叫或外部寫入，所以不是直接 RCE，但可能造成誤導性法律資訊。

**建議**
- 將檢索內容以明確 delimiter 包住，系統提示要求「忽略來源中的任何指令」。
- 對輸出做更嚴格的 citation entailment 檢查，或至少標示「引用驗證僅檢查編號，未驗證語意」。
- 高風險問題加入人工覆核或避免直接給出結論。
- 保存 prompt／answer／citation 的 provenance，方便追查。

### 12. 供應鏈與依賴風險

**證據**
- `scripts/build_frontend.py:33-41` 找不到本機 esbuild 時使用 `npx --yes esbuild`，會下載未固定版本的最新套件。
- `pyproject.toml` 依賴多為範圍約束（例如 `fastapi>=0.115,<1`、`duckdb>=1.4.5` 無上限）。
- 沒有看到 `pip-audit`、Dependabot、Renovate、SBOM 或 image digest pinning。
- Docker image 使用 tag（`postgres:16-alpine`、`qdrant/qdrant:v1.19.1`），未固定 digest。

**建議**
- 固定 esbuild 版本，使用 local dev dependency 或 lockfile，不要在 CI 使用 `npx --yes` 最新版。
- 加入 `pip-audit`／`uv-secure`、Dependabot／Renovate。
- Docker image 固定 digest。
- 建立 SBOM 與定期掃描。
- 外部字型自架，避免第三方 CSS 供應鏈。

### 13. 電源控制器與本機權限

**現況**
- 電源控制器預設綁 `127.0.0.1:9201`，這是好的。
- 但 `X-Judgment-Power: 1` 只是固定 header，不是密鑰；任何本機程序都能送出。
- `_allowed_origin` 允許 `Origin: null`（file://）與 localhost。
- `--database-url` 會出現在子程序命令列。

**建議**
- 使用隨機 token（例如 `.run/power.token`，權限 0600）取代固定 header。
- 只允許實際的 `127.0.0.1` peer，並檢查 `Host`。
- 不要用命令列傳 DB URL。
- 若不需要，設 `JUDGMENT_POWER_AGENT=0` 停用。

### 14. `FORWARDED_ALLOW_IPS=*` 與錯誤訊息

**證據**
- `.env.example:20` 與目前 `.env` 都是 `FORWARDED_ALLOW_IPS=*`。
- 多處 500 回應直接包含例外類別與訊息。

**影響**
- 任何直接連線者都可偽造 `X-Forwarded-For`／`X-Forwarded-Proto`，影響日誌、未來的 rate limit 與 audit。
- 錯誤訊息洩漏內部實作與路徑。

**建議**
- 若 cloudflared 是唯一反向代理，設 `FORWARDED_ALLOW_IPS=127.0.0.1`。
- 500 回應改為通用訊息，詳細內容只寫 server log。

## 可加強但非安全性的部分

1. **認證與角色**：目前 Google 登入仍是 pending；建議補上 viewer／admin 角色，並把管理 API 與查詢 API 分開。
2. **效能與快取**：
   - `/api/home` 當時每次載入都要 count 4,681,502 筆判決，耗時約 0.6–1.4 秒；目前已有 endpoint cache，數字以 `/api/home` 為準。
   - `/api/status` 的 `staleness` 約 3.2–3.5 秒；`/api/processing` 約 9 秒；`/api/quality` 約 8 秒。建議改用快取、背景工作或 ETag。
   - 多個使用者同時開首頁／狀態頁時，會重複執行相同重查詢；可考慮 server-side shared snapshot。
3. **RAG 索引覆蓋率**：歷史快照為 738,743 / 4,681,502（15.8%）；2026-11-21 已是 4,714,967 / 4,714,967（100%），實際值以 `/api/home` 為準。
4. **查詢索引**：`matched_laws_text LIKE '%...%'`、多欄位 `ILIKE '%keyword%'` 在 4.68M 筆上可能很慢；可加 GIN／trigram 索引或全文檢索。
5. **觀測與告警**：目前有 performance records，但沒有安全事件 audit、rate limit 告警、磁碟不足告警、異常 workflow 啟動告警。
6. **測試**：當時 350 tests 全部通過；2026-11-21 已達 697 tests，且已有安全回歸測試。以下保留當時建議：
   - 未認證呼叫 admin API 應回 401/403
   - evil origin 不應取得 CORS 允許
   - `http://127.0.0.1`／metadata IP 的 Ollama host 應被拒絕
   - 回應應有 security headers
   - `javascript:` URL 不應成為可點擊連結
   - 過大 body 應回 413
   - 超過 rate limit 應回 429
7. **備份／還原**：已有 `backup.sh`／`restore.sh`，但 `.env` 與 DB dump 未預設加密；建議加密、校驗與定期還原演練。

## P1.5 下一階段（2026-11-16 建議）

P0 已完成，以下只列現在還值得做的，按投報率排序：

1. **Security headers + CSP**（約 1–2 小時）
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: DENY`／`frame-ancestors 'none'`
   - `Referrer-Policy: strict-origin-when-cross-origin`
   - `Permissions-Policy: geolocation=(), microphone=(), camera=()`
   - HTML 回應加 CSP；`/api/*` 加 `Cache-Control: no-store`
2. **Body size 與 rate limit**（約 0.5–1 天）
   - 限制 RAG question 長度、JSON body 大小、題庫 import 筆數。
   - 對 `/api/rag/query`、`/api/rag/query/stream`、`/api/test-*`、`/api/benchmark/runs` 加 per-client 併發／速率限制。
   - 回傳 413／429 與 `Retry-After`。
3. **備份加密**（約 0.5 天）
   - `backup.sh` 目前會把 `.env`、PostgreSQL dump、Qdrant snapshot 明文寫入 removable disk。
   - 加 `--encrypt`（age 或 GPG），至少把 `config/.env` 與 dumps 加密；restore 驗證 checksum 後解密。
4. **CORS `null` 與本機信任模型**（依部署方式決定）
   - 目前 `CORS_ALLOW_ORIGINS` 含 `null`，且 loopback 請求免 admin token；任何本機 file:// 頁面都能呼叫 API。
   - 若只在單機使用，這是可接受的 local trust；若要對外或多人使用，應改成 localhost 靜態伺服器並移除 `null`。
5. **供應鏈**（可延後）
   - 固定 `esbuild` 版本、加 `pip-audit`／SBOM、Docker image digest。

### 建議現在只做 1 與 3

- Security headers 是低風險、可測試、立即降低 clickjacking／MIME sniffing／XSS 第二層風險。
- 備份加密是唯一會把 `.env` 與完整 DB 帶出場的環節，遺失成本最高。
- Rate limit 與 CORS 重構等真的對外或多人使用再做。
