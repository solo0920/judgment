# Real Question Review Guide

- 對象：`.run/real_question_audit.csv` 的 30 題第一批 trace
- 時間：約 1 小時（每題 2 分鐘）
- 目的：產生第一份人工答案品質資料；不是用 routing tag 推論品質

## 每題先看三件事

1. **條件回顯**：畫面顯示的法院、年份、關鍵詞，與問題一致嗎？
2. **前 3 筆引用**：打開判決內文，確認是否真的支持回答，不要只看案由。
3. **無依據內容**：答案是否說了引用中沒有的事，例如「雖然沒有明確說明，但可能……」？

## 標籤

| 標籤 | 定義 | 例子 |
|---|---|---|
| **答對** | 條件正確、引用支持、沒有無依據內容；清單題前 5 筆符合條件 | 士林地院 2000–2005 的違約交割只列出內文確實有該詞的判決 |
| **部分** | 方向正確但有缺口：漏了該有的、總數存疑、或有一處推論沒有依據 | 清單合理但只列部分，或敘述夾了一句沒出處的說法 |
| **答錯** | 條件不符、引用不支持敘述，或答非所問 | 問違約交割，回答違約金認定原則 |
| **應拒答未拒** | 該範圍沒有相關內容，系統卻給出自信答案；或超出資料範圍未揭露 | 資料庫沒有 1995–1997 年，卻不說明 |

「應拒答且確實拒答，並說清楚原因」算**答對**。

## 原因類別（每題一句）

- **解析**：法院、年份、詞被漏抓或誤抓。
- **檢索**：該找到的沒找到，或找到的都不相關。
- **生成**：資料沒問題，但答案說了不在資料中的內容。
- **資料**：資料庫沒有或不完整。

## CSV 欄位

```text
quality_label   answer_correct / partial / wrong / should_abstain_but_did_not
quality_reason  parsing / retrieval / generation / data，加一句說明
reviewer
reviewed_at
```

## 完成後

統計每個 `quality_label` 與 `quality_reason` 的題數。若「解析」佔多數，先修 parser；若「生成」佔多數，收緊 prompt 或不生成敘述；若「資料」佔多數，先處理 coverage，不要用 proxy 指標代替。

這份結果才是下一步工程排序的依據；`ground_truth_cases` 在人工標註前仍維持 0。
