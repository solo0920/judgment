# Feature Specification: 判決檢索與引用問答系統

**Feature Branch**: 未建立（無 `before_specify` hook；以規格目錄 `001-judgment-rag-search` 識別）

**Created**: 2026-11-06

**Status**: Partially implemented (RAG, vector search, performance report and article-level law versions implemented; Google auth and remaining version/UX requirements pending)

**Input**: 使用者提供之需求（原文）：

> # 前端
> - vanilla js
> - google auth
> - 設定選項
> - 後端狀態
> # 後端
> - fastapi
> - 資料送入rag引擎
> - rag後處理回傳至前端
> # 資料庫
> - postgres
> - indexdb
> - parquet
> - qdrant
> # 效能評估系統
> - 記錄每階段及總執行時間
> - 採用架構
> - json格式
> # 資料處理模組
> - 下載檔案
> - 使用duckdb處理資料
> - 原始data存入parquet
> - 轉換成向量檔存入qdrant
> - metadata存入postgres
> # rag引擎
> - 比對資料後取出最相關判決資料
> - 取出判決引用法規
> - 取出判決最相似的片段及使用的法規依回答格式回答
> # 回答格式
> - 簡單一二行回答
> - 判決案號列出，點擊可展開
> - 法規條號列出，點擊可展開

> **補充需求**：法規條文來源為全國法規資料庫「中文法規」<https://law.moj.gov.tw/api/ch/law/json> 與「中文命令」<https://law.moj.gov.tw/api/ch/order/json>。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 以自然語言提問並取得附引用的簡答 (Priority: P1)

一般使用者以繁體中文輸入法律問題（例如「租約到期後房東可以立刻換鎖嗎？」），系統以 1 至 2 句簡答回應，並在下方列出支撐該回答的判決案號與法規條號。使用者點擊判決案號可展開法院、裁判日期與最相關片段；點擊法規條號可展開條文內容與引用該法規的判決。

**Why this priority**: 這是產品存在的核心價值。沒有「提問→簡答→可追溯引用」的完整流程，其他功能（登入、資料匯入、效能紀錄）都無法產生使用者價值。

**Independent Test**: 在已匯入種子判決與法規資料的環境中，輸入 10 個預先定義的法律問題，確認每個問題都能在時限內取得 1 至 2 句簡答、判決案號清單與法規條號清單，且所有引用皆可展開並對應到來源資料。

**Acceptance Scenarios**:

1. **Given** 使用者已登入且搜尋索引就緒，**When** 使用者送出一個資料庫中有相關判決的問題，**Then** 系統在 5 秒內顯示 1 至 2 句簡答、判決案號清單與法規條號清單。
2. **Given** 回答已顯示，**When** 使用者點擊某個判決案號，**Then** 系統在同一頁展開案號、法院、裁判日期、與問題最相關的判決片段，以及來源連結（若來源提供）。
3. **Given** 回答已顯示，**When** 使用者點擊某個法規條號，**Then** 系統在同一頁展開法規名稱、條號、條文內容，以及引用該法規的判決案號。
4. **Given** 使用者輸入與資料庫無關或過於模糊的問題，**When** 送出提問，**Then** 系統明確顯示查無足夠相關判決，並提供調整問題的建議，不得以模型自身知識補答或虛構引用。
5. **Given** 回答中包含任何判決案號或法規條號，**When** 逐一核對，**Then** 每個引用都能對應到本次檢索使用的來源資料。

### User Story 2 - Google 登入、個人設定與後端狀態 (Priority: P2)

使用者以 Google 帳號登入後使用系統，可調整顯示偏好，並隨時確認後端服務與資料索引是否正常。

**Why this priority**: 存取控制與系統透明度是穩定使用的前提；沒有登入與狀態顯示，使用者無法判斷系統是否可信、是否可用。

**Independent Test**: 以未登入、已登入、憑證過期三種狀態測試存取行為；變更設定後重新載入頁面確認保留；中止後端服務確認狀態列與錯誤提示正確。

**Acceptance Scenarios**:

1. **Given** 使用者尚未登入，**When** 開啟網站，**Then** 系統顯示 Google 登入選項，且未登入者無法送出提問或檢視判決與法規明細。
2. **Given** 使用者擁有 Google 帳號，**When** 完成授權，**Then** 系統顯示登入身分並開放問答功能。
3. **Given** 使用者已登入，**When** 調整顯示判決數量、顯示法規數量、相似片段顯示或查詢歷史保留設定，**Then** 設定立即生效，且重新開啟網站後仍然保留。
4. **Given** 系統正常運作，**When** 使用者查看後端狀態，**Then** 系統顯示服務可用、索引已就緒與資料最後成功更新時間。
5. **Given** 後端服務中斷或降級，**When** 使用者嘗試提問，**Then** 系統顯示明確的離線或降級提示與重試操作，不得將過期結果標示為即時結果。
6. **Given** 登入憑證已過期，**When** 使用者進行需授權的操作，**Then** 系統引導使用者重新登入，且不將既有查詢結果提供給未授權對象。

### User Story 3 - 判決與法規資料匯入及索引維護 (Priority: P3)

管理者從設定的官方開放資料來源下載判決檔案，並從全國法規資料庫匯入法規與命令條文，經清理、切分與向量化後建立可搜尋索引。系統會定期檢查法規與命令是否發布新版本，發現新版時下載並加入新版資料、保留舊版與變更紀錄，且可重複執行增量更新而不中斷現有查詢服務。

**Why this priority**: 資料是新鮮度與涵蓋率的來源，但可由管理者低頻執行；核心問答可在既有資料上獨立運作，因此列為第三優先。

**Independent Test**: 以一份小型判決來源檔案執行完整匯入，確認資料可被搜尋、匯入摘要正確、重複匯入不產生重複資料；再變更法規測試來源的版本，確認系統偵測新版、匯入並保留舊版變更紀錄；最後於匯入期間發出查詢，確認服務不中斷。

**Acceptance Scenarios**:

1. **Given** 管理者已登入且具匯入權限，**When** 觸發完整匯入，**Then** 系統下載來源檔案、解析判決、建立索引，並顯示下載數、成功數、失敗數、資料版本與各階段耗時。
2. **Given** 同一批資料已匯入過，**When** 再次執行匯入，**Then** 系統更新有變更的判決、略過未變更者，且不產生重複判決。
3. **Given** 新資料正在匯入，**When** 一般使用者送出提問，**Then** 系統仍以現有索引提供查詢，並在新索引完成後才切換使用。
4. **Given** 部分來源檔案損毀或無法解析，**When** 匯入執行，**Then** 系統記錄失敗清單並可單獨重試，其餘資料仍成功匯入。
5. **Given** 匯入完成，**When** 管理者檢視任一判決，**Then** 可追溯其來源檔案、匯入批次與資料版本。
6. **Given** 一般使用者或未授權帳號，**When** 嘗試觸發資料匯入，**Then** 系統拒絕操作並記錄嘗試。
7. **Given** 管理者已登入且具匯入權限，**When** 觸發法規與命令資料匯入，**Then** 系統從全國法規資料庫「中文法規」與「中文命令」端點取得資料，建立可查詢的條文並顯示資料類型、版本、成功數與失敗數。
8. **Given** 法規與命令資料已匯入，**When** 系統執行定期或手動版本檢查，**Then** 系統比對來源版本，發現新版時下載並匯入新版資料，同時保留舊版資料與變更紀錄。
9. **Given** 新版本已匯入且舊版條文內容有變更，**When** 使用者查詢該條號，**Then** 系統預設顯示最新有效版本，並提供入口查看舊版本及變更前後內容。
10. **Given** 版本檢查或新版匯入失敗，**When** 使用者查詢該條號，**Then** 系統仍提供最後一次成功版本，並標示目前版本與更新失敗狀態。

### User Story 4 - 效能評估與可觀測性 (Priority: P3)

管理者與開發者能取得每一次提問與每一次匯入的分階段耗時、總耗時與採用架構，並以 JSON 格式匯出分析，用於比較不同檢索與回答架構的效能。

**Why this priority**: 效能評估不直接服務終端使用者，但它是驗證系統品質、進行架構決策的必要能力，因此與資料維護並列第三優先。

**Independent Test**: 執行一次提問與一次匯入，檢查各自產生的 JSON 效能紀錄是否包含所有階段、總時間、架構/設定版本與結果狀態；再確認可依時間與狀態查詢及匯出。

**Acceptance Scenarios**:

1. **Given** 一次提問完成（無論成功或失敗），**When** 檢查效能紀錄，**Then** 紀錄包含請求識別碼、各階段耗時、總耗時、架構/設定版本、檢索結果數與狀態。
2. **Given** 一次資料匯入完成，**When** 檢查效能紀錄，**Then** 紀錄包含下載、解析、切分、向量化、索引與中繼資料寫入各階段耗時、總耗時、處理數量與失敗數。
3. **Given** 管理者開啟效能頁面，**When** 選擇時間範圍與狀態，**Then** 可查看符合條件的紀錄及平均、P95 總耗時統計。
4. **Given** 某次請求在特定階段失敗，**When** 檢查紀錄，**Then** 可辨識失敗階段與錯誤類型，且不影響其他紀錄的寫入。
5. **Given** 管理者需要離線分析，**When** 執行匯出，**Then** 系統提供結構一致的 JSON 檔。

### Edge Cases

- 使用者送出空白、極長或非繁體中文的問題時，系統如何限制輸入並給予清楚提示？
- 問題只有低相似度結果、或完全沒有相關判決時，系統如何避免以模型知識補答？
- 判決引用的法規條文尚未匯入、條文已修正，或無法判定判決當時適用版本時，系統如何顯示？
- 法規 API 未提供版本或更新時間，或版本標示不一致時，系統如何判定是否發布新版？
- 新版本刪除、移列或整併條號時，舊條號如何查詢與呈現？
- 版本檢查排程中斷或長時間未執行時，系統如何避免誤判最新有效版本？
- 同一案號存在不同審級、更審或不同資料版本時，系統如何辨識與呈現？
- 來源檔案缺漏、壓縮檔損毀、編碼錯誤或格式變更時，匯入如何處理？
- 匯入過程中断或服務重啟時，如何避免資料重複、半寫入或索引不一致？
- 後端、關聯式資料庫、向量索引或語言模型其中一項故障時，系統如何降級並告知使用者？
- Google 授權被取消、憑證過期，或帳號不在管理者允許清單時，系統如何處理？
- 使用者在匯入進行中重複觸發匯入時，系統如何避免同時執行？
- 使用者引用的判決或法規在展開前已被新資料版本取代時，系統如何保持顯示內容一致？
- 瀏覽器停用本機儲存或使用無痕模式時，個人設定與查詢歷史如何處理？

## Requirements *(mandatory)*

### Functional Requirements

#### 帳號與存取

- **FR-001**: 使用者 MUST 能透過 Google 帳號登入；未登入者不得送出提問或檢視判決與法規明細。
- **FR-002**: 系統 MUST 顯示目前登入狀態並提供登出操作；登出後不得再存取需授權的內容。
- **FR-003**: 登入憑證失效或過期時，系統 MUST 要求使用者重新登入，且不得將既有查詢結果提供給未授權對象。
- **FR-004**: 只有被授權的管理者 MUST 能觸發資料下載、匯入與索引切換；一般使用者僅能查詢。
- **FR-005**: 系統 MUST 記錄每次資料匯入的觸發者、時間、來源與結果，以供稽核。

#### 問答與引用

- **FR-006**: 使用者 MUST 能以繁體中文自然語言輸入問題並送出；系統 MUST 對空白、過短或超過長度上限的輸入提供明確限制與提示。
- **FR-007**: 系統 MUST 針對每次提問回傳 1 至 2 句簡答（簡答本文不得超過 2 句）。
- **FR-008**: 簡答 MUST 以檢索到的判決內容為依據；系統不得生成未出現在來源資料中的判決案號、法規條號或條文。
- **FR-009**: 系統 MUST 找出與問題最相關的判決，並在回答中列出其判決案號。
- **FR-010**: 系統 MUST 找出每筆相關判決中與問題最相似的片段，並標示該片段所屬判決及其中使用的法規。
- **FR-011**: 系統 MUST 從相關判決中擷取被引用之法規條號，並列於回答中。
- **FR-012**: 使用者點擊判決案號時，系統 MUST 在原頁展開案號、法院、裁判日期、最相關片段與來源連結（若來源提供）。
- **FR-013**: 使用者點擊法規條號時，系統 MUST 在原頁展開法規名稱、條號、條文內容，以及引用該法規的判決案號。
- **FR-014**: 引用明細 MUST 可收合，且展開與收合不得重新載入頁面。
- **FR-015**: 查無足夠相關判決時，系統 MUST 明確顯示無結果訊息並提供調整問題的建議，不得以模型自身知識補答。
- **FR-016**: 判決引用的法規條文未收錄或無法取得時，系統 MUST 顯示條號並標示條文內容暫缺及原因。
- **FR-017**: 法規條文 MUST 標示版本或生效日期；無法判定判決當時適用版本時，系統 MUST 顯示提醒。
- **FR-018**: 回答、引用與介面文字 MUST 以繁體中文呈現。
- **FR-019**: 檢索結果超過顯示上限時，系統 MUST 顯示剩餘筆數並允許使用者載入更多。
- **FR-020**: 回答頁 MUST 顯示免責聲明，說明內容僅供參考、不構成法律意見。

#### 設定與系統狀態

- **FR-021**: 系統 MUST 提供設定頁，至少可調整：顯示判決數量（預設 3，範圍 1–10）、顯示法規數量（預設 5，範圍 1–10）、是否顯示相似片段（預設顯示）、是否保留本機查詢歷史（預設不保留）。
- **FR-022**: 設定變更 MUST 立即套用並保存於使用者裝置，重新開啟網站後仍然生效。
- **FR-023**: 使用者 MUST 能清除本機查詢歷史並將所有設定恢復為預設值。
- **FR-024**: 系統 MUST 顯示後端狀態，包括服務可用性（可用／降級／離線）、搜尋索引是否就緒、資料最後成功更新時間；狀態至少每 30 秒更新一次，並提供手動刷新。
- **FR-025**: 後端離線或降級時，前端 MUST 顯示明確提示與重試操作，且不得將快取或過期資料標示為即時結果。
- **FR-026**: 瀏覽器不支援或停用本機儲存時，系統 MUST 以預設設定運作並提示使用者設定無法保存。

#### 資料處理與索引

- **FR-027**: 管理者 MUST 能從設定的官方資料來源下載判決資料，並支援完整匯入與增量匯入兩種模式。
- **FR-028**: 資料處理流程 MUST 保留原始檔案、清洗後資料與索引產物，且每筆判決可追溯至來源檔案與匯入版本。
- **FR-029**: 系統 MUST 解析判決的案號、法院、裁判日期、全文與引用法規，並建立可供語意相似度檢索的片段表示。
- **FR-030**: 系統 MUST 以案號與裁判日期（及資料版本）辨識判決；重複匯入不得產生重複資料。
- **FR-031**: 資料匯入 MUST 分階段執行（下載、解析、切分、向量化、索引、中繼資料寫入），任一階段失敗不得破壞現有可查詢資料。
- **FR-032**: 新資料索引完成前，搜尋 MUST 繼續使用現有索引；索引切換 MUST 以原子性方式完成。
- **FR-033**: 系統 MUST 提供匯入摘要，包含下載檔案數、成功與失敗判決數、各階段耗時、資料版本與完成時間。
- **FR-034**: 損毀或無法解析的檔案與判決 MUST 記錄於失敗清單並可單獨重試，不得中斷整批匯入。
- **FR-035**: 系統 MUST 防止同一時間重複執行匯入；已有匯入進行中時，必須顯示目前狀態並拒絕或排隊新的匯入請求。
- **FR-036**: 管理者 MUST 能查詢目前資料版本、判決總數、索引狀態與最近一次匯入結果。
- **FR-037**: 系統 MUST 支援管理者從全國法規資料庫「中文法規」端點（<https://law.moj.gov.tw/api/ch/law/json>）與「中文命令」端點（<https://law.moj.gov.tw/api/ch/order/json>）匯入與更新法規及命令條文，並保留資料類型（法規／命令）、版本或生效日期；未匯入時依 FR-016 處理。
- **FR-038**: 系統 MUST 支援不停機的增量更新，更新期間查詢服務維持可用。

#### 法規版本管理

- **FR-048**: 系統 MUST 支援定期與管理者手動檢查「中文法規」與「中文命令」端點是否發布新版本；定期檢查預設至少每日一次，並記錄檢查時間、來源、結果與耗時。
- **FR-049**: 偵測到新版法規或命令時，系統 MUST 下載並匯入新版本，且保留既有舊版本資料，不得以新版本覆蓋或刪除舊版本。
- **FR-050**: 舊版本條文內容有變更時，系統 MUST 產生變更紀錄，至少包含條號、變更前後內容、變更欄位、新舊版本識別、生效日期與偵測時間，並可供使用者與管理者查詢。
- **FR-051**: 顯示法規或命令條文時，系統 MUST 以最新有效版本為主；若使用者或判決引用特定舊版本，系統 MUST 提供切換或連結以查看該舊版本及其變更紀錄。
- **FR-052**: 判決引用之條文存在多個版本時，系統 MUST 標示判決當時適用版本，並在可判定時顯示該版本與最新版本之差異。
- **FR-053**: 新版本刪除、移列或整併條號時，舊條號 MUST 仍可查詢，並標示其現行狀態及對應的新條號（若可判定）。
- **FR-054**: 版本檢查或新版匯入失敗時，系統 MUST 保留最後一次成功版本、標示更新失敗狀態並允許重試，不得以不完整資料取代可查詢版本。
- **FR-055**: 版本檢查、新舊版本與變更紀錄 MUST 納入管理者可查詢的匯入／版本歷程，並記錄於效能紀錄。

#### 效能評估

- **FR-039**: 每次提問 MUST 產生一筆效能紀錄，包含請求識別碼、時間、各階段耗時（檢索、重排、法規擷取、答案生成、後處理）、總耗時、採用的架構／設定版本、檢索結果數與成功或失敗階段。
- **FR-040**: 每次匯入 MUST 產生一筆效能紀錄，包含下載、解析、切分、向量化、索引與中繼資料寫入各階段耗時、總耗時、處理數量、失敗數與架構版本。
- **FR-041**: 效能紀錄 MUST 以 JSON 格式保存，欄位名稱與結構需一致，並可供匯出。
- **FR-042**: 系統 MUST 提供管理者檢視效能紀錄與統計，至少包含平均與 P95 總耗時，並可依時間範圍與狀態篩選。
- **FR-043**: 效能紀錄 MUST 包含足夠的架構與設定資訊（例如模型、索引與參數版本），以支援不同架構之間的比較。
- **FR-044**: 效能紀錄 MUST 避免包含不必要的個人資料；使用者識別須以不可逆的識別碼表示。
- **FR-045**: 請求失敗時，系統 MUST 仍寫入效能紀錄並標示失敗階段與錯誤類型。
- **FR-046**: 效能紀錄 MUST 至少保留 90 天，且單一紀錄寫入失敗不得中斷使用者請求。
- **FR-047**: 系統 MUST 能將效能紀錄以 JSON 檔匯出，供離線分析。

### Key Entities *(include if feature involves data)*

- **使用者 (User)**: 以 Google 身分識別的使用者；具有顯示名稱、角色（一般使用者／管理者）與個人顯示設定。
- **判決 (Judgment)**: 一筆裁判書；包含案號、法院、裁判日期、全文、來源資訊與資料版本。案號與裁判日期為主要識別依據。
- **判決片段 (Judgment Segment)**: 判決中可供檢索的文本片段；包含所屬判決、片段順序、文字內容、語意表示與相似度分數。
- **法規與命令條文 (Law/Order Article)**: 法規或命令之名稱、條號、條文內容、資料類型（法規／命令）、版本或生效日期、現行狀態與版本歷程。
- **法規版本變更紀錄 (Law Version Change)**: 條號、舊版與新版識別、變更欄位、變更前後內容、生效日期與偵測時間。
- **版本檢查作業 (Version Check Run)**: 一次版本檢查的來源、檢查時間、發現的新版本、匯入結果與失敗原因。
- **判決引用法規 (Judgment–Law Citation)**: 判決與其引用之法規或命令條號之間的關係；可包含引用上下文與判決當時適用版本。
- **提問 (Query)**: 使用者送出的原始問題、送出時間與使用者識別碼。
- **回答 (Answer)**: 1 至 2 句簡答、引用判決清單、引用法規清單與免責聲明。
- **顯示設定 (Display Settings)**: 判決顯示數量、法規顯示數量、是否顯示相似片段、是否保留本機查詢歷史。
- **資料匯入批次 (Ingestion Run)**: 一次下載與匯入作業；包含來源、資料版本、觸發者、開始與完成時間、各階段統計與狀態。
- **效能紀錄 (Performance Record)**: 一次提問或匯入的分階段耗時、總耗時、架構／設定版本、結果狀態與錯誤資訊，以 JSON 表示。
- **後端狀態 (Backend Status)**: 服務可用性、索引就緒狀態與資料最後更新時間。
- **查詢歷史 (Query History)**: 儲存於使用者裝置的近期提問與回答摘要（可選擇關閉）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 50 位同時使用者的正常負載下，95% 的提問能在 5 秒內完成並顯示簡答與引用。
- **SC-002**: 100% 顯示的判決案號與法規條號可追溯至本次檢索的來源資料；驗收測試中不得出現任何虛構引用。
- **SC-003**: 在至少 100 題、由法律專業人員建立的基準問題集上，至少 80% 的提問其前 5 筆檢索結果包含一筆被評為相關的判決。
- **SC-004**: 至少 90% 的提問在首屏即包含一筆判決引用；若相關判決有引用法規，首屏亦包含至少一筆法規條號。
- **SC-005**: 至少 90% 的受測者能在 1 次點擊內展開引用，並於 10 秒內看到裁判日期、相關片段或條文內容。
- **SC-006**: 100% 的提問與匯入執行都產生有效的 JSON 效能紀錄，且包含各階段與總耗時。
- **SC-007**: 管理者能在 1 分鐘內取得最近一次匯入的成功／失敗、處理數量與總耗時摘要。
- **SC-008**: 增量匯入 10,000 筆判決能在 2 小時內完成，且更新期間查詢服務可用率不低於 99%。
- **SC-009**: 重複匯入同一批資料產生 0 筆重複判決；100% 的已索引判決可追溯至來源檔案與資料版本。
- **SC-010**: 對查無相關結果的基準問題，100% 顯示明確的無結果訊息，且產生 0 筆虛構引用。
- **SC-011**: 至少 90% 的首次使用者無需額外說明，即可完成一次提問並展開引用。
- **SC-012**: 在支援本機儲存的瀏覽器中，使用者設定於重新開啟網站後 100% 保留。
- **SC-013**: Google 登入成功率至少 99%（排除使用者主動取消授權）。
- **SC-014**: 後端中斷或恢復後，前端狀態顯示能在 30 秒內反映最新狀態。
- **SC-015**: 在定期檢查啟用且來源正常回應的情況下，來源發布新版法規或命令後，系統能在 24 小時內完成偵測與匯入。
- **SC-016**: 100% 的舊版條文變更都具備可查詢的變更紀錄，且紀錄包含變更前後內容、版本識別與生效日期。
- **SC-017**: 100% 的法規與命令條文查詢預設顯示最新有效版本；使用者可在 2 次點擊內切換查看舊版本與變更內容。
- **SC-018**: 版本檢查或新版匯入失敗時，0 次以不完整的新版本取代可查詢的舊版本；查詢服務維持可用。

## Assumptions

- 目標使用者位於台灣，主要使用繁體中文；判決與法規均為台灣資料。
- 判決資料來源為司法院裁判書開放資料或政府資料開放平臺，實際匯入範圍與排程由管理者設定。
- 判決相關檔案的儲存根目錄由 `specs/002-judgment-data-storage` 定義，預設為 `/data/judgments`；原始檔、清洗後資料、Parquet 資料集、儲存清單與暫存檔均位於其下。
- 判決納入檢索範圍依 `specs/003-law-cited-judgment-filter` 定義：僅納入明確引用 `documents/金融法規.md` 所列法規的判決；未符合者保留原始檔，但不進入索引與資料庫。
- 法規與命令條文來源為全國法規資料庫開放 API：中文法規 <https://law.moj.gov.tw/api/ch/law/json>、中文命令 <https://law.moj.gov.tw/api/ch/order/json>，由管理者匯入並保留版本或生效日期；未匯入時，系統僅顯示判決中提及的條號並標示條文暫缺。
- 本規格所稱「法規」涵蓋全國法規資料庫之「法規」與「命令」兩類條文資料。
- 版本檢查以來源 API 提供的版本識別或更新時間為主；來源未提供時，系統以條文內容雜湊比對判斷是否變更。
- 系統預設每日檢查一次法規與命令版本，管理者可調整排程或手動觸發。
- 最新有效版本依來源標示之生效日期與狀態判定；若來源未提供，則以最近一次成功匯入且生效日最新的版本為準。
- 法規與命令的舊版本及變更紀錄永久保留，不適用效能紀錄的 90 天保留規則。
- 使用者指定的技術堆疊視為不可變更的限制：前端使用 vanilla JavaScript；後端使用 FastAPI；資料儲存使用 PostgreSQL、Qdrant、Parquet 與 DuckDB；瀏覽器端使用 IndexedDB；身分驗證使用 Google。功能需求本身不依賴特定框架。
- 系統為單一租戶服務；初期設計容量為 100 萬筆判決與 50 位同時使用者。
- 任何 Google 帳號皆可登入查詢；管理者權限以允許清單設定。
- 回答由可替換的語言模型與語意嵌入模型產生；模型、提示與索引版本須記錄於效能紀錄，以便比較不同架構。
- 後端為前端唯一的資料來源；IndexedDB 僅儲存顯示設定與可選的本機查詢歷史，不儲存完整判決資料。
- 判決與法規屬公開資料，使用與顯示須遵守來源的授權條款與標示要求。
- 系統提供資訊檢索與摘要，不構成法律意見；所有回答頁均顯示免責聲明。
- 效能紀錄保留至少 90 天；查詢文字可用於品質分析，使用者識別以不可逆識別碼表示。
- 使用者具備可執行現代網頁瀏覽器的裝置與穩定網路連線。

## Out of Scope

- 使用者上傳自有文件、建立私人知識庫或個人化模型。
- 生成法律書狀、契約、正式法律意見或訴訟策略。
- 案件管理、計費、多人協作與權限細分（除一般使用者與管理者外）。
- 原生行動應用程式。
- 繁體中文以外語言的問答與翻譯。
- 判決全文的人工編輯、更正或內容審核流程。
- 即時爬取非開放授權或需付費的資料來源。
- 語音輸入與語音輸出。
